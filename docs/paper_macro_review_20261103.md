## 故障、修复与验证

Windows PowerShell Operational 在北京时间 **13:51:16** 的事件 4100 记录：原 `start_paper_services.ps1` 以 `ErrorActionPreference=Stop` 执行 Python 并合并重定向日志，Python stderr 中的 `Exception in thread Thread-3379 (_readerthread):` 被转为终止错误，启动循环随即停止。事件 403 记录该 PowerShell 引擎停止；同期没有发现系统重启证据。

修复 `scripts/install_paper_services_task.ps1` 的启动模板：仅在原生 Python 调用期间临时使用 `Continue`，保存退出码后由 `finally` 恢复原错误策略。已有 0／73／78 不重试、其他退出码退避重试的逻辑保持。生产启动脚本部署同一最小块，不调用安装器重新注册服务或恢复已取消实验。

这修复的是已证实的启动循环退出问题。原始 Python reader thread 的完整 traceback 没有保留，底层线程异常原因尚未确认，不将编码假设写成既定根因。

真实 Windows PowerShell 子进程回归覆盖 stderr 加退出码 0／73／78、非零失败后的 10／20 秒退避计算、错误策略恢复及其他启动错误仍终止；测试仅替代等待。相关主盘、监督器、趋势、跨市场与资料新鲜度回归为 **222 passed**，另启动修复与原监督器回归 **18 passed**。

维护证据位于 `data/research/paper_macro_review_20261103/`：原主盘在本次操作前已停止，维护先核对进程身份与写入锁，再保存全部 102 个账户、元数据和金融历史固定字节前缀。恢复使用原账本和 `--require-existing`，只启动 `main` 与 `btc_signals`；只读观察器、终端及 98 个取消账户保持。恢复后的实际状态以 `verified_live.json` 为准，不以旧 `running=true` 字段或单纯进程存在宣称行情健康。
