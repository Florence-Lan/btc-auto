# 公共行情回退与信号诊断修订（2026-10-25）

本轮修复无法解析的公共 API `code` 导致备用请求被跳过的问题，并补齐时钟及信号过滤日志。均线、四小时确认、价格触发、止损、仓位、手续费与资金费规则保持；模拟账户和实验沿用原账本。

**响应回退**

原 `int(payload.get('code', 0))` 遇到 `code:null` 等不可解析值可能抛出未进入备用路径的异常。现在将这些值归类为 `InvalidPublicResponse / api_code_invalid`，沿用原来两条传输、一次备用请求的上限。合法负错误码和 HTTP 418／429 仍按原规则处理，不额外重试或绕过冷却。保留原有可解析错误码兼容行为，不宣称实现了新的严格 API schema。

此缺陷由离线注入复现，不等于之前每次真实超时都是它造成。修复可恢复有有效备用数据的请求，不能消除上游断网。

**时钟诊断**

时钟校验保持请求成功样本耗时不超过五秒、原始收到时间不超过十五秒，以及原有格式／时序限制。校验异常仍继承 `ValueError`，原接口兼容；新增固定原因码以区分无效载荷、无效时间戳、无效计时、成功请求过慢和接收过期。

诊断区分真实回调的 `network` 耗时与共享请求调用者的 `caller_wait` 耗时。成功时钟返回独立 `_public_clock_attempts` 元数据，原始 `_public_clock_timing` 收到时间不变；共享读不重盖时间，也不增加请求。全失败时的安全聚合错误保留两次原因和耗时，避免原 160 字符截断隐藏备用通道；仅此已清洗错误允许展示至 1,024 字符，其它异常维持原限制。

原因、耗时、scope、错误类别等均走白名单和有限数值校验；原始异常消息、请求 URL、代理凭证及任意未知字段不进入新增诊断输出。TLS、代理选择、公开端点白名单、限流冷却和工作线程预算不变。

**信号日志**

保留原 `raw_signal` 字段的旧语义：四小时确认与质量过滤之后、研究方向／时段过滤之前。新增 `signal_diagnostics` 显式保存确认前、确认后、质量过滤后及研究策略后的候选，以及分层原因和 `signal_candidate_only` 作用域。候选被信号管线允许不代表通过资金、行情、财报、盘口或最终执行检查。

原始候选为空时，即使四小时背景不合格，也记作 `no_raw_signal`，不误计为真实候选被拒。信号只生成一次，四小时和质量过滤的计算及短路顺序保持。原 `signal_at` 返回 `signal_with_diagnostics(...)[0]`；主引擎现在直接取得这份诊断及同一个最终信号，成交决定保持，没有补算旧信号或回填历史日志。

**验证**

UTF-8 模式最终全量 Python 回归：**2,111 项通过、2 项跳过、43 个 subtests 通过**。新增回归覆盖请求优先和 curl 优先的坏响应回退、全失败关闭、限流、共享接收时间、耗时口径、诊断隐私、真实多空信号分层和现价盘口成交。旧的成交、资金费、保护退出和过期校验断言保留。

测试夹具作了相应修正：将旧 wrapper 的假信号注入移到原始信号层；共享时钟测试保持源时间、单请求与副本隔离断言，同时允许各调用者等待时间不同；到期前一毫秒的边界测试固定单调时钟，避免测试运行本身跨过期限，真实耗时跨期测试仍保留。本轮没有界面修改。
