# 已收K线缓存周期修复（2026-10-29）

本次修复一个已复现的数据时序缺陷：请求批次的交易所时钟尚在整点之前，处理完成时跨过整点，旧代码却按处理完成时刻认证缓存周期。旧小时线可能因此被当作新周期已更新，下一轮跳过重取，额外等待一个五分钟缓存周期。

例如，11:59:58 的时钟对应的已收小时线仍截止11:00；处理在12:00:01完成后，不能将这批数据认证为12:00周期的新数据。正常HTTP响应但缺少最新完整K线，以及时钟失败，也不能给缓存认证。

## 修改范围

`StockAccount.step` 现在仅在以下条件全部满足时认证缓存：本批时钟有效，信号及五分钟数据获取成功且非空，它们各自的最后一根K线都等于该时钟应有的最新完整K线。认证周期取本批交易所时钟的五分钟桶。信号刷新未能通过这些检查时清除认证，下一轮重新获取。

小时突破、完整四小时确认、财报保护、追价上限、止损、目标、杠杆和单笔风险预算均保持原配置。新风险继续要求有效行情；已有仓位的独立有效标价和盘口保护路径保持原样。

此次修复解决分钟级额外等待。此前MU、SKH在12点形成信号后的成交时序均不到一分钟，原审计所见的小时级等待来自四小时趋势确认、事件窗口和新突破条件；本次修复不能被称为已经解决全部早期转向或趋势延续覆盖问题。
