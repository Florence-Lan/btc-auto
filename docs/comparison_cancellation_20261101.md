# 取消全部对照盘

用户明确要求“取消当前的所有对照盘”。本次停止全部 8 组、98 个独立对照账户，并关闭其自动恢复入口。北京时间 **2026-11-01 02:04:11** 完成取消状态归档；各组停止后的最后市场时间保留在原状态中，没有刷新成归档时间。

| 对照组 | 账户数 | 停用方式 |
| --- | ---: | --- |
| SNDK 四小时确认 | 4 | 监督器 `sndk_shadow.enabled=false` |
| BTC 再入场 | 4 | 监督器 `btc_reentry_shadow.enabled=false` |
| 股票宏观过滤 | 12 | 监督器 `stock_macro_shadow.enabled=false` |
| 股票退出响应 | 24 | 禁用并停止原计划任务及其启动进程树 |
| 股票早期恢复 | 12 | 禁用并停止原计划任务及其启动进程树 |
| 股票入场时机 | 18 | 禁用并停止原计划任务及其启动进程树 |
| 科技板块过滤 | 12 | 禁用并停止原计划任务及其启动进程树 |
| 快速空头确认 | 12 | 禁用并停止原计划任务及其启动进程树 |

监督器配置为 `config/paper_service_extensions_20261020.json`。新增严格布尔开关 `sndk_shadow.enabled`；未配置时保留原兼容行为，明确禁用后既不拉起 SNDK 对照，也不因其历史账本或冻结代码目录不可用而阻止主服务启动。BTC 再入场和宏观过滤沿用已有开关。

只结束 worker 会被 PowerShell 循环或每分钟计划任务重启，因此先核对精确任务动作、工作目录和进程创建时间，再禁用任务并结束受控进程树。监督器内的三组必须通过配置排除；维护期间短暂停止并恢复原监督器任务，恢复后其服务列表只有 `main`、`btc_signals`。没有初始化新的主账户。

主模拟盘的四个账户、规则、净目标 100 / 风险预算 25、创建时间和 manifest 均保持。重启后实际主 worker 为 **33732**，主盘 44 个源码指纹匹配。主盘自己的时钟接口仍保留；已停止的入场时机对照所提供的共享时钟缓存失效后，会按原逻辑回退到该接口。只读跨市场观察服务与界面继续运行。

全部对照状态元数据已标为 `running=false`、`status=cancelled_by_user`，每组新增 `cancellation_20261101.json`。原账户 state、成交、资金费、余额、performance、manifest 及已记录的历史前缀不由取消工具改写；旧状态文件原文和最后账户快照分别保存在取消证据目录中。

取消时仍有 **10 个对照账户持有模拟 SNDK 空仓位**，位于退出响应、入场时机和科技过滤三组。它们随实验停止而冻结，保留最后一次实际观察的估值；没有制造平仓成交，也没有把未实现收益计为已实现。原主盘的 SNDK 持仓仍由主盘正常管理。

验证：服务构建/禁用路径 **30 项定向测试通过**，完整测试 **2970 passed, 2 skipped, 43 subtests passed**。实际服务构建只返回主盘及 BTC 信号服务，五个独立恢复任务均已禁用，八个对照 runner 无活动进程。原 98 个账户与 **496 份成交/资金费等历史文件**在停用后进行哈希检查，另跨越原每分钟恢复周期复核没有续写或重启。

证据目录：`data/research/cancel_comparisons_20261101/`，包括 `before_experiments.json`、任务身份快照、`cancelled.json` 和最终 `final_verification.json`。停用前仍运行期间产生的正常行情/估值变化保留；没有将旧快照恢复覆盖到最终账本。
