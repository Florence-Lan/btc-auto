# 公共数据可靠性与 Brent 合约维护

本次落实 10 月 26 日评估中的维护项目：公共请求诊断、冷却状态可靠性、观察器重试和临期合约审查。均线、四小时确认、止损、仓位、交易成本、入场有效期及 LLM 工具链保持原值。

## 请求与冷却

审计发现，部分重复校时和价格复核是在资金费抓取或 LLM 检查之后执行的安全步骤；当前没有足够的实际请求权重记录，不能认定本机超额是这次限流的原因。因此没有缓存交易所时钟／标记价格，也没有对所有公共请求增加统一限速来挤占保护性行情通道。

新增可选的 Binance 公共请求诊断。受管理的模拟盘启动器通过 `BINANCE_PUBLIC_DIAGNOSTICS=1` 启用；默认关闭。记录固定端点、实际网络发送／响应／传输失败、本地冷却拦截，以及有效的服务端 `X-MBX-USED-WEIGHT-1M` 数字。没有记录请求参数、密钥、原始响应、任意报错正文或客户端 IP。

诊断文件为 `data/runtime/binance_public_reads.json`，按最近 60 个 UTC 分钟聚合，最大 256 KiB。锁竞争、文件损坏或时钟回退时拒绝写入，不刷新或重置成完整统计，也不影响原请求结果。它明确标记为尽力记录，不能代表共享出口的全部流量或交易所配额。

冷却记录增加跨进程锁，对已有暂停期限执行最长值合并；支持 HTTP 日期形式的 `Retry-After`。真实请求派发和备用传输前再次检查冷却。首次限流记录若因锁忙或发布失败而无法落盘，同一进程的所有客户端仍保留最长已知期限，继续阻止请求。跨进程传播仍依赖可写存储，写盘失败会显式失败，不声称所有进程都已获知新记录。

既有 `data/runtime/binance_api_cooldown.json` 保持原字节，最早重试时间仍为 **2026-10-27 09:00:05.723 北京时间**，不保证届时一定恢复。没有向受限 Binance 端点发送部署探测，也没有切换主机或传输绕过限制。

## 观察器重试

观察配置显式启用瞬时传输故障的退避：60、120、240 秒递增，最多 900 秒；成功的日频源仍按原 6 小时周期采集。没有增大单次超时、并发或同轮请求数。

这些是最早重试时间；实际请求仍受原有五分钟采集循环约束，不承诺每分钟发送请求。

HTTP 403／429 保留至少一小时、正常轮询周期及完整 `Retry-After` 中最长的等待；身份、解析、TLS 和代理错误不会获得快速重试。失败、缓存命中与时钟回退均不会更新行情观察时间或首次可用时间。上线前已承诺的旧等待时间不提前；新策略从后续失败开始生效。
