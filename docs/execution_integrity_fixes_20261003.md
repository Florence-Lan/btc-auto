## 执行前重查当前限制

原先，首次出现信号时的因子决定会固定在目标上，而执行账户没有重查当前事件窗口、因子许可与公共来源健康。因此，旧目标重试或加仓可能绕过当前禁入限制。

新增 `scripts/execution_entry_gate.py`，由模拟和实盘执行器在执行前调用。它重新读取当前快照，用实际执行时间、拟执行方向与原报告固定的因子配置校验日历、因子时效、方向许可和必需来源健康。日历和来源健康使用同一次 JSON 读取；配置变化、快照损坏、来源过期或执行时钟不可用均阻止新增风险。生产模拟在 LLM/provider 返回后再次获取交易所时钟，覆盖等待期间跨入事件窗口的情形。

禁止新增风险时，直接在数量上限制目标：空仓不能入场，同向不能加仓，反转只允许关闭旧方向；持有、减仓、平仓和账户硬止损照常处理。这也覆盖同一 `position_id` 的重复执行及先前未达到最小交易数量的旧目标。首次观察时固定的因子仓位倍率仍保留，当前检查负责执行许可。

## 小时目标的可用时点

原先仅向冻结小时引擎提供已收盘 K 线。引擎会在下一根小时 K 线开盘执行待入场信号，但线上要等这一根小时线收盘后才看到持仓，从而落后于完整历史回放。

新增 `scripts/timeseries_execution.py` 和 `scripts/execution_portfolio.py`，执行模型为 `closed_signal_known_open_v1`。EMA、波动率和信号仅使用已收盘小时线，追加一个已知开盘价格的观察点，让待执行目标在开盘时可用。该点不读取正在形成的小时线高、低、收盘价和成交量；开盘滑点与规模估计使用上一根已收盘小时线的流动性。组合与目标流显式记录 `available_time_ms`，在已知开盘边界识别目标。

开盘观察不提前确认影子账本的小时资金费，实际执行账户仍按结算时刻的真实模拟持仓结算资金费。冻结信号引擎 `simulate_range_swing.py`、原账本 `execution_ledger.py`、原风控 `portfolio_risk.py`、冻结候选与六因子配置均保持原有哈希。8% 软降仓、15% 锁定平仓等阈值未调整。
