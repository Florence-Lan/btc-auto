# 公共行情故障隔离与保护恢复（2026-10-16）

已按用户要求修复程序侧的公共行情备用读取、故障隔离与风控时间参照问题，并在北京时间 **10 月 16 日 23:23:53** 后启用到原模拟服务。BTC、MU、SNDK、SKHYNIX 及四个 SNDK 影子账本继续运行，仍为 `SIMULATION / places_orders=false`。策略信号、仓位预算、止盈止损参数和入场条件的配置文件未变。

本轮验证目标是：新数据可用时辅助源错误不阻断已有保护；数据不可用时不增加风险、不使用过期行情制造成交；启用修复不重置账户或实验历史。

**查明的原因与边界。** 当前两家交易所及其他站点经过同一个本机 TUN 网络出口。历史长中断同时涉及多个站点的 TLS/连接超时；原日志抹去了底层错误，无法据此进一步断言是节点、DNS 或 TLS 中哪一个故障。两种 HTTP 工具使用不同 TLS 实现，但不构成两条独立网络路线。本轮没有修改本机代理、TUN、DNS 或 TLS 校验设置。

程序中另有可复现的问题：股票账户在保护检查前验证时钟、指数价、合约资料和蜡烛数据，部分异常会提前退出整轮；坏时钟可能覆盖旧时间参照；BTC 在所有时钟解析失败后未继续尝试独立行情保护，回退校验也可能受主机时间跳变影响；部分截断/损坏响应未尝试备用读取。

**修复内容。**

- [公共传输诊断](../scripts/public_transport.py)保留安全的异常类型链、errno、Windows 错误码和 curl 退出码，记录两次尝试的失败分类，避免把代理凭据、请求原文写入日志。curl 子进程保留代理/证书配置及必要 Windows 环境变量。
- [Binance 客户端](../scripts/binance_terminal_client.py)和 [Aster 客户端及账户循环](../scripts/run_parallel_simulation.py)对截断响应、内容解码失败、无效 JSON 等进行有界的同端点备用读取。Aster 成功使用 curl 后短期优先使用它，避免每轮重复等待已失败的主传输。HTTP 418/429 仍遵守冷却，不通过切换工具继续请求。
- 股票的辅助数据异常隔离为降级状态；已有仓位在新鲜标记价、新鲜盘口及有效数量规则齐备时，继续按原有规则处理保护退出。缺少盘口只保留待退出状态，不虚构成交。过期标记价仍拒绝，并先保存保护失败状态；缺少标记价也不刷新最后成功行情或改写持仓。
- 股票时钟先作为候选参照验证，再经原有行情新鲜度规则交叉检查，成功后才提交新锚点；坏时钟不污染旧参照。主机时间落后八秒的原有兼容性测试保留，行情最大年龄 60 秒、最多未来五秒的限额没有放宽。
- [BTC 时钟解析](../scripts/decision_runtime.py)将已验证的行情及实际验证参照传给 [风险监测](../scripts/simulation_risk_monitor.py)，以单调时间计龄。主机时间跳变不会误拒已验证的新行情；旧/未来行情继续拒绝。失去交易所时钟时仍只尝试独立保护，不运行策略新增风险或进行资金费截止结算。
- 每次保护检查记录成功时间、行情时间、失败计数和可执行状态，区分进程心跳与实际保护可用性。

